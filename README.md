## The short version

This is one research and engineering program, expressed as separate instruments:

```text
knowledge + simulation  →  RISK//MESH  →  investigation / challenge  →  decision forensics
freight fraud            →  evidence + provenance + explicit capability boundaries
AI governance            →  controls, documents, implementation gaps, and audit trails
```

The repositories are not a single deployed product. Where a connection exists, it is an explicit adapter, fixture, or hash-verified snapshot. Static GitHub Pages cannot launch a local Python service, and unavailable providers are surfaced as unavailable.

![Current verified ecosystem architecture](assets/ecosystem-architecture.svg)

The diagram shows the current verified boundary, not a target architecture: solid lines are implemented/local, dashed lines are snapshots or optional paths, muted lines are unavailable or outside the repository pipeline, and amber markers identify simulated data.

## Flagship systems

### [RISK//MESH](https://github.com/Jeevan-0508/Risk-Mesh) · [Observatory](https://jeevan-0508.github.io/Risk-Mesh/observatory/)

Risk-intelligence fabric for contracts, evidence, provenance, cases, arbitration, and learning across independent risk systems.

**Visual proof:** [open the neural Observatory](https://jeevan-0508.github.io/Risk-Mesh/observatory/) — a real orb-and-ledger replay of captured golden cases and System-1 shadow runs.

**Status:** `LOCAL` contracts and engines · `SNAPSHOT` Observatory data · Laya `SHADOW` checkpoints when the runtime is available · Jev `UNAVAILABLE` · no production traffic. The Observatory is a replay of captured cases, not a live cross-repository feed.

### [Fraud Watch](https://github.com/Jeevan-0508/fraud-watch) · [Live demo](https://jeevan-0508.github.io/fraud-watch/)

An adversarial fraud-evolution laboratory: a synthetic freight world produces observable behaviour, signals, investigations, candidate mutations, and analyst-reviewed outcomes while hidden intent remains inaccessible to the analyst.

![Fraud Watch](https://raw.githubusercontent.com/Jeevan-0508/fraud-watch/main/docs/live-sim.png)

**Status:** `SIMULATED` synthetic world · `DETERMINISTIC` seeded engines · scheduled GitHub Action advances persisted snapshots · no machine learning and no real operational data.

### [RISK//SWARM](https://github.com/Jeevan-0508/risk-swarm) · [Live demo](https://jeevan-0508.github.io/risk-swarm/)

Seven-agent risk investigation with evidence provenance, disagreement, red-team review, governance gates, and a recommendation that remains subject to human decision.

![RISK//SWARM](https://raw.githubusercontent.com/Jeevan-0508/risk-swarm/main/docs/command-center.png)

**Status:** `DEMO` uses pinned, hash-verified snapshots with no key and no network · `SNAPSHOT` mode preserves the same knowledge against the real clock · provider-backed paths are `OPTIONAL` and must fail closed.

### [RISK//REPLAY](https://github.com/Jeevan-0508/risk-replay) · [Live demo](https://jeevan-0508.github.io/risk-replay/)

Decision forensics and counterfactual replay: reconstruct a recorded decision, mutate evidence or inputs, and inspect what changes under the declared replay model.

![RISK//REPLAY](https://raw.githubusercontent.com/Jeevan-0508/risk-replay/main/frontend/src/assets/hero.png)

**Status:** Pages demo is `SNAPSHOT`/static with synthetic data and no LLM in the decision path · FastAPI backend is `LOCAL` and separately testable · replay is not a claim about real-world causation.

### [POLICY//AUDIT](https://github.com/Jeevan-0508/policy-audit) · [Live demo](https://jeevan-0508.github.io/policy-audit/)

Client-side governance evidence auditor that traces regulation → control → implementation → evidence → gap, including contradictions and policy/implementation conflicts.

**Status:** `LOCAL`/`DETERMINISTIC` browser engine · optional LLM enhancement is not wired into the shipped build · no backend, account, or upload service.

### [Freight Risk Atlas](https://github.com/Jeevan-0508/freight-risk-atlas) · [Live demo](https://jeevan-0508.github.io/freight-risk-atlas/)

Structured freight-fraud assessment engine that reports indicator coverage, evidence completeness, false-positive gates, and stage-appropriate countermeasures without pretending to estimate fraud probability.

![Freight Risk Atlas](https://raw.githubusercontent.com/Jeevan-0508/freight-risk-atlas/main/docs/screenshots/0-landscape.png)

**Status:** `LOCAL`/`DETERMINISTIC` browser tool · open taxonomy model · no incident data and no probability claim.

## Verification principles

- Capability labels are explicit: `LIVE`, `LOCAL`, `SNAPSHOT`, `FIXTURE`, `SIMULATED`, `DETERMINISTIC`, `OPTIONAL`, or `UNAVAILABLE`.
- Evidence is separated from claims; replay is separated from causation; coverage is separated from probability.
- Synthetic worlds are labelled synthetic, and provider failures are visible rather than replaced with invented output.
- The strongest demos are linked above; their READMEs contain architecture, setup, tests, security notes, and limitations.
